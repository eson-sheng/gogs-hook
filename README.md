# Gogs Web Hook

接收 Gogs 的 Webhook 推送，在指定的本地或远程 Git 仓库中更新分支。支持从推送数据自动识别分支，以及在远程更新成功后重载 Nginx。

## 1. 部署准备

钩子服务器需要能够运行 PHP，且允许调用 `exec`。本地更新需要安装 Git；远程更新还需要 SSH 客户端，目标服务器需要安装 Git。开启远程重载时，目标服务器还需要安装 Nginx。

1. 将本项目部署到 PHP 网站目录，以 `index.php` 为入口。
2. 将 `.example.env` 复制为项目根目录的 `.env`，配置签名密钥和允许更新的目标。
3. 在目标服务器提前克隆业务仓库，确认部署目录的 `origin` 指向正确的仓库，并且执行更新的系统用户具有目录写入权限和仓库拉取权限。
4. 在 Gogs 仓库中添加 Webhook，填写请求地址，使用 JSON 请求体，填写与 `.env` 相同的密钥，并订阅 Push 推送事件。

本程序更新已有仓库，不会自动克隆仓库、创建部署目录、安装依赖或执行构建脚本。

## 2. 请求参数

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| `r` | 是 | 目标服务器上现有 Git 仓库的绝对部署路径，例如 `/usr/local/lxhub` |
| `b` | 否 | 指定允许部署的分支，仅推送分支与其一致时更新；不传或为空时，从已验证签名的请求体 `ref` 识别分支，不再默认使用 `master` |
| `o` | 否 | 远程服务器 IP 或主机名；不传或为空时在钩子服务器本机更新，传入时通过 SSH 以 `root` 用户执行 |
| `s` | 否 | 仅字符串 `true` 开启远程 Nginx 重载；其他值均不开启。未传 `o` 时忽略 |

参数优先从 URL 查询字符串读取，其次读取普通 POST 表单字段。JSON 请求体用于签名校验和分支识别，不用于读取 `r`、`b`、`o`、`s`。包含特殊字符的参数值应进行 URL 编码。

### 只传 r：本机更新推送分支

```text
http://120.78.9.49:82/?r=/usr/local/lxhub
```

若 Gogs 推送内容为：

```json
{
  "ref": "refs/heads/w",
  "after": "bb790fefc5d006faf0f79feaaea0ce12345c829a",
  "repository": {
    "name": "lxhub-lua",
    "full_name": "vvsai/lxhub-lua"
  },
  "commits": [
    {
      "modified": ["vvsai/app/api/controller/demo.lua"]
    }
  ]
}
```

程序会在钩子服务器本机的 `/usr/local/lxhub` 更新 `w` 分支。该目录需要加入 `ALLOWED_TARGETS` 的 `local` 数组。

`r` 是完整部署目录，不会拼接仓库名 `lxhub-lua`，也不会根据 `commits.modified` 选择更新目录。程序从部署目录已有的 `origin` 拉取，不使用请求中的 `clone_url`，也不校验 `repository.name` 与目标仓库是否一致。请为对应仓库配置正确的 Webhook 地址和密钥。

### 传 r、o：远程更新推送分支

```text
http://120.78.9.49:82/?r=/usr/local/lxhub&o=112.74.83.111
```

收到 `refs/heads/w` 时，通过 SSH 登录 `root@112.74.83.111`，在远程 `/usr/local/lxhub` 更新 `w` 分支。

需要更新成功后重载远程 Nginx 时，加上 `s=true`：

```text
http://120.78.9.49:82/?r=/usr/local/lxhub&o=112.74.83.111&s=true
```

### 显式传 b：只允许指定分支触发更新

```text
http://120.78.9.49:82/?r=/usr/local/lxhub&b=w&o=112.74.83.111&s=true
```

显式传入非空的 `b=w` 后，仅当推送数据为 `ref: refs/heads/w` 时更新。其他分支（例如 `master` 或 `feature/w`）返回 HTTP 200，并在 `data` 中提示“推送分支与配置的 b 不一致，跳过更新”，不执行 Git、SSH 或 Nginx 命令。分支名区分大小写，按完整名称精确匹配。

### 自动识别分支的规则

未传 `b` 或 `b` 为空时，自动选择推送分支；传入 `b` 时，还须满足上述分支精确匹配规则。请求体解析和删除分支规则对两种模式都生效：

| 推送数据 | 处理方式 |
| --- | --- |
| `ref: refs/heads/w` | 更新 `w` 分支 |
| `ref: refs/heads/feature/demo` | 更新 `feature/demo` 分支，保留完整分支名 |
| 有分支 `ref`，且 `after` 为 40 个 `0` | 视为删除分支，返回成功并跳过 Git 更新及 Nginx 重载 |
| 标签推送，例如 `refs/tags/v1.0.0` | 返回 HTTP 406，不执行更新 |
| 无效 JSON、缺少 `ref`、非字符串或空分支 `ref` | 返回 HTTP 406，不执行更新 |

实际更新前，分支名还会由 `git check-ref-format` 检查，检查失败时返回执行错误。无论是否传入 `b`，都需要有效的分支推送 JSON；标签推送或无效请求体返回 HTTP 406。匹配分支的删除事件也会跳过更新。

## 3. .env 配置

配置文件位于钩子项目根目录，不是业务仓库目录。可以从示例文件复制：

```sh
cp .example.env .env
```

本机和远程部署同时启用的示例：

```ini
; 与 Gogs Webhook 中填写的密钥一致，部署前替换。
GOGS_SIGNATURE = '替换为你的随机强密钥'

; 精确授权每台服务器可以更新的目录。
ALLOWED_TARGETS = '{"local":["/usr/local/lxhub"],"112.74.83.111":["/usr/local/lxhub"]}'

; 远程 Nginx 的默认可执行文件。
NGINX_BIN = 'nginx'

; 可选：按远程服务器覆盖 Nginx 路径。
NGINX_BINS = '{"112.74.83.111":"/www/server/nginx/sbin/nginx"}'
```

### 目标白名单 ALLOWED_TARGETS

- `local` 是本机模式的保留键，不能作为 `o` 的值。
- 其他键必须与 `o` 中填写的 IP 或主机名完全一致。同一服务器使用域名与 IP 时，需要分别授权。
- 每个数组只允许该服务器上的指定目录。可以填写多个目录，但不支持通配符、子目录继承或自动拼接。
- 目录必须精确匹配绝对路径，不允许 `.`、`..` 路径段或空字节。本机目录必须存在，并且与 `realpath` 后的规范路径一致，不带末尾斜杠。
- 远程目录必须提前存在；路径不存在或不是有效 Git 仓库时，会在远程执行阶段报错。远程目录及父目录应由管理员管理，避免被替换为符号链接。
- 未配置、无效 JSON、缺少对应服务器或目录不在数组中时，拒绝部署。

只在远程部署时，可以只配置：

```ini
ALLOWED_TARGETS = '{"112.74.83.111":["/usr/local/lxhub"]}'
```

此时只传 `r` 的本机更新请求会被拒绝，需要同时传入 `o=112.74.83.111`。

### Nginx 路径配置

远程请求同时满足有效 `o` 和 `s=true` 时，按以下顺序选择可执行文件：

1. `NGINX_BINS` 中与 `o` 精确匹配的路径。
2. `NGINX_BIN` 的值。
3. 两者均未指定路径时使用 `nginx`。

只填写可执行文件路径或名称，不要附加参数或命令。不同服务器可分别配置：

```ini
NGINX_BIN = '/usr/sbin/nginx'
NGINX_BINS = '{"112.74.83.111":"/www/server/nginx/sbin/nginx","192.168.1.100":"/usr/local/nginx/sbin/nginx"}'
```

远程重载请求若映射不是 JSON 对象，或选中的路径为空、不是字符串或包含空字节，会在 Git 更新前返回 HTTP 500。本机或未开启重载时不检查该映射。路径映射不会授予服务器访问权限，仍需配置 `ALLOWED_TARGETS`。

## 4. Git 更新及重载流程

验证请求签名、解析分支并检查目标配置后，本地和远程使用相同的 Git 更新流程。以 `w` 分支为例：

```sh
cd /usr/local/lxhub &&
git check-ref-format refs/heads/w &&
git fetch origin +refs/heads/w:refs/remotes/origin/w &&
git checkout -f -B w refs/remotes/origin/w &&
git reset --hard refs/remotes/origin/w
```

程序从 `origin` 获取分支最新提交，强制切换或创建本地分支，并将已跟踪文件对齐到获取的远端分支。不执行 `git pull` 合并；本地额外提交及已跟踪文件的未提交修改会被覆盖，也支持同步远端强制推送。部署的是本次 fetch 获取的分支最新状态，不保证固定在推送数据的 `after` 提交。

获取失败（包括远端分支不存在）时，不继续执行后续步骤。步骤之间使用 `&&` 连接，但整个过程不是事务；后续失败不会回滚已完成的步骤。

未跟踪和被忽略的文件通常保留，不执行 `git clean`。如果这些文件阻挡远端已跟踪文件的检出，Git 可能覆盖它们，部署数据应独立保存。本流程不包含子模块和 Git LFS 的额外同步。

远程更新成功且 `s=true` 时，继续在远程服务器执行：

```sh
nginx -t && nginx -s reload
```

实际执行文件由 Nginx 路径配置决定。配置检查失败时不执行 reload；检查或重载失败均返回错误，但已完成的 Git 更新不会回滚。`s` 只控制这一组固定命令，不支持自定义脚本，也不会重载本机 Nginx。

## 5. SSH 与执行权限

远程模式使用：

```sh
ssh -o BatchMode=yes -o ConnectTimeout=10 root@112.74.83.111 '远程更新命令'
```

运行 PHP 的系统用户必须能够通过 SSH 密钥免密登录目标 `root` 用户，并提前确认目标主机密钥，将其加入该系统用户的 `known_hosts`。SSH 使用默认端口及该用户的 SSH 配置，连接超时为 10 秒，认证不会交互式询问密码。

权限分为两段，需要分别确认：

- 钩子服务器上运行 PHP 的用户：能够读取 `.env`、执行 Git／SSH，本机更新时能够写入业务目录。
- 远程服务器上的 `root` 用户：能够写入业务目录、从业务仓库的 `origin` 拉取代码，开启重载时能够执行 Nginx。

应使用实际运行 PHP 的系统用户测试连接，不能仅凭管理员账号下 SSH 成功就判断 Webhook 具有相同权限。私有仓库还需要为实际拉取代码的用户配置仓库访问凭据。

## 6. 签名与接口保护

所有请求均要求 `X-Gogs-Signature` 请求头，值为使用 `GOGS_SIGNATURE` 对原始请求体计算的 SHA256 HMAC（64 位十六进制字符串）。密钥未配置、签名缺失或签名不匹配时，返回 HTTP 401，不执行更新。直接在浏览器中打开示例地址不会完成部署，需要由 Gogs 发送带有效签名的请求。

Gogs 签名保护请求体，不绑定 URL 中的目标、分支和重载参数，也不能防止有效请求被重放。生产环境应使用 HTTPS 并限制接口访问来源。以上 HTTP 地址用于展示现有部署的参数写法。

Web 服务必须禁止直接访问 `.env` 和 `.example.env`，避免暴露配置。返回数据可能包含 Git／SSH 命令输出，应限制接口的可访问范围。

## 7. 返回结果与排查

响应格式：

```json
{
  "msg": "OKAY",
  "code": 1,
  "data": ["Git 或 SSH 的执行输出"]
}
```

`code` 是业务状态码，与 HTTP 状态码不同。成功执行且没有命令输出时，`data` 可以是空数组。

| HTTP 状态 | 业务码 | 含义及检查方向 |
| --- | --- | --- |
| 200 | 1 | 更新成功；分支不匹配或删除分支也返回成功，`data` 提示跳过更新 |
| 401 | 110 | 签名错误，检查 `.env` 密钥、Gogs 密钥及签名请求头 |
| 403 | 304 | 服务器或目录未授权，检查 `ALLOWED_TARGETS` 与 `r`、`o` 是否精确匹配 |
| 406 | 301 | 缺少部署目录 `r` |
| 406 | 302 | 本机目录不存在或不是规范路径 |
| 406 | 303 | `o` 地址格式错误，或使用了保留值 `local` |
| 406 | 305 | 参数不是字符串，例如传入了 `r[]` |
| 406 | 306 | 缺少有效分支 `ref`，检查 JSON 请求体和推送事件 |
| 500 | 501 | Git、SSH 或 Nginx 执行失败，查看 `data` 中的输出定位原因 |
| 500 | 502 | Nginx 路径配置无效，检查 `NGINX_BINS` 与选中的路径 |

若同时存在多个错误，响应以实际首先执行的检查为准。例如签名始终先校验；分支解析和跳过判断在目录校验前进行。

常见执行错误包括：目录不是 Git 仓库、`origin` 配置错误、远端分支不存在、仓库凭据不可用、文件权限不足、SSH 主机密钥未确认、免密登录失败，以及 Nginx 路径或配置错误。

## 8. 本地验证

项目提供隔离配置及模拟 Git／SSH／Nginx 命令的集成测试，需要本机安装 PHP 和 Python 3，并允许监听临时本机端口：

```sh
python3 tests/security.py
```

测试覆盖签名校验、目标白名单、自动分支识别、显式分支匹配及不匹配跳过、无效推送、删除分支跳过，以及远程 Nginx 重载配置。测试不会连接真实部署服务器，也不会更新实际业务仓库。测试脚本位于开发工作目录的 `tests/` 中，当前 `.gitignore` 忽略此目录；若部署副本不包含该目录，则无法运行该命令。
