# Gogs Web Hook
> 接收`gogs`的`push`推送，自动更新项目到最新节点。

## 部署配置说明
> eg:

- 推送地址设置
```
http://xxx:888/?r=/home/www/item/path&b=master
```
**参数说明：**

| 参数名称 | 说明作用 |
| :------------ | :------------ |
| `r`  | 项目在服务器里面的部署路径 |
| `b`  | 仓库分支，默认为`master` |
| `o`  | 可选，远程服务器 IP 或主机名。传入后通过 SSH 以 `root` 用户执行更新；不传则在本地执行 |
| `s`  | 可选，仅字符串 `true` 开启。仅在传入有效 `o` 时，远程 Git 更新成功后执行 `nginx -t && nginx -s reload`；不传 `o` 时忽略 |

远程更新示例：
```
http://xxx:888/?r=/home/www/item/path&b=master&o=192.168.1.100
```
需要更新后重载远程 Nginx 时，在地址后加 `&s=true`。远程 SSH 环境的 `PATH` 中需要有 `nginx`。配置检查或重载失败会返回错误，但已完成的 Git 更新不会回滚。

`s` 只控制固定命令，不接收自定义脚本。所有请求必须携带有效的 `X-Gogs-Signature`（原始请求体的 SHA256 HMAC）；缺失、错误签名或缺少密钥均返回 401。服务器和目录还必须匹配 `.env` 白名单，否则返回 403。

`.env` 配置示例（将密钥换成随机强密钥，并与 Gogs Webhook 配置一致）：
```ini
GOGS_SIGNATURE = '替换为你的随机强密钥'
ALLOWED_TARGETS = '{"local":["/home/www/local-app"],"192.168.1.100":["/home/www/item/path"]}'
```
`local` 是本地模式的保留键，不能用作 `o`。其他键必须与 `o` 的 IP／主机名完全一致，每个键的数组只允许该服务器上的指定目录。未配置、空数组、无效 JSON 均拒绝访问。目录必须精确匹配绝对路径，不支持通配符或子目录匹配，不允许 `.`／`..` 路径段。本地目录需填写 `realpath` 后的规范路径，不带末尾斜杠。远程白名单目录及父目录应由管理员管理，避免被替换为符号链接。

Gogs 签名只保护请求体，不能绑定 URL 中的分支及 `s`，也不能防止有效请求被重放。请使用 HTTPS 并限制接口访问来源；签名有效的请求仍能在配置的目标内选择分支和触发重载。Web 服务需禁止直接访问 `.env`（包括 `.example.env`）。
此时 `r` 是远程服务器上的项目路径。本地和 SSH 模式使用相同的更新流程：从 `origin` 获取指定分支的最新提交，强制切换／创建本地分支，并通过 `git reset --hard` 对齐到远端分支。不使用 `git pull` 合并，因此本地额外提交、已跟踪文件的未提交修改都会被覆盖，远端强制推送也能同步。获取失败（包括远端分支不存在）时停止更新。

未跟踪和被忽略的文件通常会保留（如 `.env`、上传文件），不执行 `git clean`。但如果这些文件阻挡远端已跟踪文件的检出，Git 可能覆盖它们；部署数据应独立保存。本流程保证普通仓库中已跟踪文件和分支提交与本次获取的 `origin` 分支一致，不包含子模块和 Git LFS 的额外同步。

运行 PHP 的系统用户需要能够通过 SSH 密钥免密登录 `root@192.168.1.100`，并事先确认目标主机的主机密钥（`known_hosts`）。远程服务器也需要安装 Git，并具备仓库拉取权限。SSH 使用默认端口及该用户的 SSH 配置；连接超时为 10 秒，认证不会交互式询问密码。

- 密钥设置需要和`web钩子`的秘钥文本保持一致，
此项目的`.example.env`有示例。

- 配置文件去除前缀，命名为`.env`就可配置完毕。
